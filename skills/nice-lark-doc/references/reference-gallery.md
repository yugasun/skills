```xml

  </column>
  <column width-ratio="0.333">

      <p><b>治理边界</b></p>
      <ul>...</ul>

```

**适用场景**：技术方案、架构设计、产品方案等需要快速传达核心决策的文档。

#### 2. 章节：数字编号 + 混合内容

```
h2: 1. 背景与目标
  - 段落 + 加粗引导句
  - 无序列表（核心能力、目标）
  
h2: 2. 设计原则
  h3: 2.1 原则一
    - 段落 + 列表
  h3: 2.2 原则二
  
h2: 3. 系统架构
  - 段落引入
  - **画板**（SVG 架构图）
  - 段落解释
  
h2: 13. 可观测与复盘
  - 段落 + **画板**（Mermaid 时序图）
  
h2: 14. System Prompt
  - <pre> 代码块
  
h2: 15. 总结
  - 段落 + 黄色高亮关键句
  - 无序列表
  - <callout> 升级路径
```

**关键技巧**：
- h2 用数字编号（1. 2. 3...）
- 段落开头用 **加粗引导句**："**评级 Agent 1.0 已实现以下核心能力**："
- 关键术语用 `<span background-color="rgba(255,246,122,0.8)">` 黄色高亮
- 画板紧跟在段落解释之后，形成"文字→图表→解释"节奏

#### 3. 结尾：总结 + 任务分工

```xml
<h2>15. 总结</h2>
<p>一段话概括核心思想...</p>
<p><span background-color="rgba(255,246,122,0.8)">关键结论句</span></p>
<ul>
  <li>要点一</li>
  <li>要点二</li>
</ul>

<callout emoji="🎯" background-color="rgb(255,245,235)" border-color="rgb(254,212,164)">
  <p><b>升级路径（待讨论）</b></p>
  <ul>...</ul>
</callout>

<h2>任务分工</h2>
<ol>
  <li><b>模块名</b> <cite>负责人</cite>

  </li>
</ol>
```

### 总结：这份文档的优点

1. **结构清晰**：开篇三栏 Callout 快速传达核心决策，章节数字编号层次分明
2. **视觉节奏好**：段落→列表→画板→Callout 交替出现，无文字墙
3. **色彩语义明确**：蓝色=主流程，紫色=反馈优化，橙色=数据，绿色=成功
4. **对比度优秀**：所有文字与背景对比度达标，白色文字只用在深色节点上
5. **画板设计专业**：容器用极浅色底 + 彩色边框，卡片统一白底，连线颜色与语义一致
6. **高亮克制**：黄色高亮只用于关键术语，不过度使用

**值得借鉴的设计决策**：
- 使用 Tailwind CSS 色板（业界标准，色彩和谐）
- 容器用极浅色底（#eff6ff 级别）而非纯色填充
- 卡片统一白底 + 彩色边框（而非彩色填充）
- 连线颜色与模块颜色一致（蓝模块用蓝连线，紫反馈用紫连线）
- 虚线表示反馈/跨层，实线表示主流程

## 文档 002：Agent Skill 评估与演进

**文档链接**：https://a0t3ktpwj6.feishu.cn/docx/AiaSdkutgoLEXvxhweEctlxgnQf  
**Recipe 风格**：技术严谨（tech-structured）  
**画板数量**：8 个（3 SVG + 5 Mermaid）  
**特点**：章节节奏感极强、Callout 语义色系统完善、Mermaid 多类型混用、表格与画板交替呈现

### 文档结构模式

#### 1. 开篇：标题 + 核心判断 Callout

```xml
<title>Agent Skill 评估与演进：从"能跑"到"可回归"</title>

<callout background-color="rgb(240,244,255)" border-color="rgb(130,167,252)" emoji="📌">
  <p><b>核心判断：</b>一段话概括全文核心观点，加粗关键词...</p>
</callout>
```

**适用场景**：观点型技术文档、方法论文章、决策建议。开篇即用 Callout 给出结论，读者可以在 3 秒内抓住全文要旨。

#### 2. 章节节奏：段落 → 视觉元素 → Callout 总结

每个 h2 章节遵循统一的三段式节奏：

```
h2: N. 章节标题
  - 1-2 段引入文字（解释为什么讨论这个话题）
  - 视觉元素（表格 / Mermaid 图 / SVG 画板）
  - 可选：Callout 总结（提炼本节核心概念或约束）
```

**关键技巧**：
- h2 用数字编号（1. 2. 3...），共 10 节，层次扁平不嵌套 h3
- 每节只有 1-2 个视觉元素，不贪多
- 段落控制在 2-3 段以内，绝不出现文字墙
- 视觉元素类型在章节间交替变化：表格→画板→表格→画板

#### 3. 结尾：行动项 Checkbox + 约束 Callout + 讨论表格

```xml
<h2>8. 接下来怎么做</h2>
<p>引导段落...</p>
<whiteboard>...</whiteboard>

<checkbox done="false"><b>行动项标题。</b>具体描述...</checkbox>
<checkbox done="false"><b>行动项标题。</b>具体描述...</checkbox>

<callout background-color="rgb(254,241,241)" border-color="rgb(249,142,139)" emoji="🚫">
  <p><b>关键约束。</b>不可妥协的底线...</p>
</callout>

<h2>9. 讨论问题</h2>
<table>... 序号 / 讨论问题 / 关键决策点 ...</table>
```

### Callout 四色语义系统

该文档的 Callout 使用堪称典范——四种颜色各司其职，读者扫一眼颜色就知道信息类型：

| 语义 | background-color | border-color | emoji | 用途 | 出现位置 |
|---|---|---|---|---|---|
| **核心判断** | `rgb(240,244,255)` | `rgb(130,167,252)` | 📌 | 全文结论、核心观点 | 开篇 |
| **概念/洞察** | `rgb(254,255,240)` | `rgb(255,242,88)` | 💡 | 核心概念定义、设计约束 | 章节总结 |
| **重要前提** | `rgb(240,251,239)` | `rgb(142,224,133)` | 💡 | 前提假设、边界声明 | 章节总结 |
| **禁止/底线** | `rgb(254,241,241)` | `rgb(249,142,139)` | 🚫 | 不可妥协的约束、安全红线 | 关键警告 |

**设计原则**：
- 每节最多 1 个 Callout，不扎堆
- Callout 永远放在视觉元素之后，作为"本节 takeaway"
- 加粗关键词 + 句号分隔：`<b>核心概念。</b>解释文字...`
- 红色 Callout 全文仅 1 个，稀缺性保证其警示力度

### 表格设计模式

#### 表头样式

所有表格统一使用灰色表头：

```xml
<th background-color="rgb(242,243,245)" vertical-align="top">
```

#### 表格用途分类

| 用途 | 列数 | 示例 | 特点 |
|---|---|---|---|
| **对比表** | 3 | 传统软件 vs Agent Skill | 第一列为维度名，后两列对比 |
| **矩阵表** | 3-4 | 评估对象 × 问题 × 示例 | 第一列加粗，行之间逻辑递进 |
| **清单表** | 3-4 | 序号 × 类型 × 目标 × 状态 | 用 emoji（✅🔶）标记状态 |
| **受众表** | 3 | 受众 × 关注点 × 报告形式 | 按角色分行 |
| **讨论表** | 3 | 序号 × 问题 × 决策点 | 开放式问题结构化 |

**设计原则**：
- 表格用于"结构化对比"和"多维分类"，不用于叙述
- 第一列通常是分类维度，加粗或用简短名词
- 列宽比例约 1:2:2 或 1:3:2，第一列窄、内容列宽
- 状态列用 emoji（✅ 可自动化 / 🔶 人工）而非纯文字

### Mermaid 多类型混用策略

该文档是 Mermaid 画板混用的优秀范例，5 个 Mermaid 画板覆盖 4 种图表类型：

| 章节 | 图表类型 | 用途 | 选择理由 |
|---|---|---|---|
| §2 评估对象 | **mindmap** | 展示评估维度全景 | 树状发散结构，一眼看全貌 |
| §4 多轮会话 | **sequenceDiagram** | 展示用户-Agent-工具交互 | 多方参与、有时序、有分支 |
| §5 报告受众 | **flowchart TB** | 展示生产者→平台→消费者 | 有方向的流转关系 |
| §6 最小套件 | **mindmap** | 展示用例分类全景 | 树状分类，快速概览 |
| §7 编译关系 | **flowchart LR** | 展示循环反馈链路 | 有回路的流程，左右布局 |

**选型规则**：
- 展示"有哪些" → mindmap
- 展示"谁和谁交互" → sequenceDiagram
- 展示"怎么流转" → flowchart（TB 用于层级，LR 用于链路）
- 展示"自定义/品牌化" → SVG 画板

**Mermaid 内嵌文字技巧**：
- 节点文字用 `<br>` 换行：`DEV[研发工程师<br>自测与回归]`
- subgraph 分组：`subgraph 生产者 ... end`
- alt/else 表达分支：`alt 数据缺失 ... else 高风险判断 ... end`
- 反馈回路用带标签的边：`ANA -->|反馈| DEV`

### SVG 画板与 Mermaid 的分工

| 特征 | SVG 画板（3 个） | Mermaid 画板（5 个） |
|---|---|---|
| 出现位置 | §1 背景、§3 分层模型、§8 行动 | §2、§4、§5、§6、§7 |
| 用途 | 概念关系图、分层架构、路线图 | 思维导图、时序图、流程图 |
| 设计自由度 | 高（自定义色彩、布局、图标） | 低（语法约束） |
| 信息类型 | 抽象概念、层级关系 | 具体流程、交互、分类 |

**分工原则**：标准图表类型（思维导图、时序图、流程图）用 Mermaid 快速生成；需要品牌化设计、自定义布局或抽象概念表达时用 SVG。

### Checkbox 行动项模式

```xml
<checkbox done="false"><b>选一条主链路。</b>近期只围绕阶段一设计 Eval，不提前纳入后续阶段。</checkbox>
<checkbox done="false"><b>先做小而真实的 Golden。</b>从高频问题中选 5-10 个样本...</checkbox>
```

**设计原则**：
- 加粗短语作为行动项标题（≤ 10 字）
- 句号后接具体描述
- 按优先级排列
- 配合前置画板（路线图）使用，画板给全景，checkbox 给执行

---

### 总结：这份文档的设计理念

1. **结论前置**：开篇 Callout 即给出核心判断，不让读者猜
2. **节奏如呼吸**：段落→视觉→总结，每节三段式，读者不疲劳
3. **色彩即语义**：蓝=结论、黄=洞察、绿=前提、红=禁止，扫色即知类型
4. **表格做对比，画板做关系**：结构化数据用表格，概念/流程/交互用画板
5. **Mermaid 够用就不 SVG**：标准图表类型优先 Mermaid，省时且可编辑
6. **稀缺性原则**：红色 Callout 全文仅 1 个，Checkbox 集中在行动章节
7. **扁平层次**：10 个 h2 不嵌套 h3，每节自包含，适合跳读

**值得借鉴的设计决策**：
- 用 Callout 颜色建立"信息类型视觉索引"，读者可以只看蓝色和红色
- 表格第一列窄（分类维度），后列宽（内容），比例约 1:2:2
- Mermaid mindmap 用于"全景概览"，flowchart 用于"流转关系"，sequence 用于"多方交互"
- 行动项用 Checkbox 而非有序列表，暗示"可勾选完成"的心理模型
- 讨论问题用表格结构化（序号×问题×决策点），比纯列表更适合会议讨论
