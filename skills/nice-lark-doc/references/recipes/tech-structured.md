# 技术严谨 Recipe

结构化、层次分明、画板和表格辅助理解。适合技术团队内部评审、需要精确定义的技术内容。

## 设计系统

### 标题体例
- 使用数字编号：1. → 1.1 → 1.1.1
- 不使用中文大编号（一、二、三）
- h1 只用于文档标题，正文从 h2 开始
- 最多 3 层标题

### 段落规则
- 叙述性内容保持成段，段落控制在 3-5 句
- **连续纯文本段落不超过 3 段**，第 4 段前必须插入视觉元素
- 技术定义用加粗引导句：**「术语。」** 解释内容
- 避免连续超过 2 个无标题的纯文本段落

### 视觉打断规则
- 每个 h2 章节必须有至少 1 个画板 + 1 个表格
- 每 2-3 段叙述后，用以下方式打断：
  - 参数/配置 → 表格
  - 流程/架构/时序 → 画板
  - 关键约束/前提 → callout
  - 对比分析 → 表格
- 技术方案类文档，画板数量 ≥ h2 章节数

### 表格使用
- 高频使用表格呈现：对比、参数、状态矩阵、接口定义
- 表格必须有表头，表头用 light-gray 背景
- 复杂数据用多列表格，不超过 5 列
- 每个 h2 章节至少 1 个表格

### 画板策略
- 首选飞书画板，**每个 h2 章节至少 1 个画板**
- 技术方案文档的画板数量应 ≥ h2 章节数
- **路径选择**：
  - 系统架构 / 组件关系 → SVG（大胆设计，色彩区分模块）
  - 数据流转 / 请求链路 → SVG（流程图，正交折线连接）
  - 时序图 / 接口调用顺序 → Mermaid（sequenceDiagram）
  - 数据库结构 → Mermaid（erDiagram）
  - 状态变迁 → Mermaid（stateDiagram）
  - 项目排期 → Mermaid（gantt）
  - 分类体系 → Mermaid（mindmap）
- SVG 画板充分利用色彩区分模块、渐变高亮关键路径

### SVG 画板最低配额
- **技术方案类文档**：至少 1 个 SVG 画板（优先用于系统架构图或核心流程图）
- **必须使用 SVG 的场景**（不可用 Mermaid 替代）：
  - 分层架构图（多层容器嵌套 + 色彩编码模块）
  - 核心业务流程图（需要语义色彩区分路径：成功/失败/警告/紧急）
  - 系统关系图（需要自定义布局，非标准图类型）
  - 时间轴 + 泳道流程图（如发布流程、审批流程）
- **SVG 设计质量底线**：
  - 至少使用 3 种语义色（参考 `flowchart-theme.md` 或 `color-palette.md`）
  - 节点不能全用矩形，至少有一种非矩形形状（药丸形、圆角、图标）
  - 必须有视觉层次（主流程 > 次流程 > 辅助信息）
  - 禁止"白底 + 黑框 + 黑字"的默认样式

### 高亮块 (callout)
- 用于：关键约束、重要前提、安全警告、设计决策
- 每个 h2 章节可 1-2 个
- 语义色：警告用 red、注意用 yellow、说明用 blue、推荐方案用 green

### Checkbox
- 用于行动项和验收标准
- 不用于普通列表

### 颜色语义
- 配色模式：**单色渐变** 或 **双色对比**
- 主色调：品牌蓝 #0050E0 家族（#0050E0 → #60A0E0 → #93C5FD）
- 语义色按需使用：成功 #16A34A / 警告 #CA8A04 / 风险 #DC2626
- 不用纯黑，用 #1E293B 替代
- 详见 `references/color-palette.md`

### 字号参考
- h2: 18pt
- h3: 14pt
- h4: 12pt
- 正文: 12pt
- 行间距: 标准

### 可视化转译指南
以下内容应转为视觉元素，不用纯段落：
- 系统架构 / 组件关系 → 飞书画板（架构图）
- 数据流转 / 请求链路 → 飞书画板（流程图）或 mermaid（时序图）
- 接口参数 / 配置项 → 表格
- 状态变迁 → 飞书画板（状态机）或 mermaid（stateDiagram）
- 方案对比 / 选型分析 → 表格
- 关键约束 / 非功能性需求 → callout
- 数据库结构 → 飞书画板（ER 图）

### 整体节奏
```
1. 背景与目标（2-3 段 + 现状架构画板）
  ↓
2. 现状分析（表格对比 + 问题总结 callout）
  ↓
3. 方案设计（架构图 + 编号子章节 + 每个子方案有表格/画板）
  ↓
4. 实施计划（表格 + checkbox + 甘特图画板）
  ↓
5. 风险与回滚（风险表格 + 关键约束 callout）
```
