# 做深，而不是做大

把原任务改写为顶尖专业人士会实际执行、结果可以被独立检验的任务。先明确专业工作缺在哪里，再重写提示词；交付的是更准确的任务要求，不是代为完成原任务。

深度来自问题判断、原始证据、领域方法和独立验收，不来自更多篇幅、功能、章节或研究主题。

## 一、固定原任务边界

从上下文明确：为谁解决什么问题、结果用于什么决定、交付什么，以及范围、时间、预算等约束。

保留这些边界。新增动作必须直接提高原结果的可靠性，优先替换浅层做法，而非叠加工作量。资源有限时，先验证最可能改变结论的问题，缩减低价值步骤，不擅自增加资源要求或删减原定交付。

利用已有上下文补齐信息。只有缺口会改变任务目标、方法或可行性且无法自行查明时才提问；其余缺口标注假设，或在新提示词中要求执行者确认。无需为了设计任务，先做完研究、取得全部材料或运行全部验证。

## 二、重写前，逐项回答四问

显式输出以下四项诊断。每项围绕当前任务给出具体内容，而不是复述通用原则。

### 1. 顶尖专业人士会做什么，而原任务没有要求？

指出最影响结果的 1–3 个遗漏动作，并说明为什么会改变判断或成果质量。

用可执行动作，例如复现故障、核对分母、检查样本偏差、比较替代解释、测量瓶颈、寻找反例。用该领域的方法说明专业性，不靠“全面分析”“最佳实践”或专家身份背书。

只选择服务原目标的必要动作。若原任务已经要求某动作，说明它需要加深的具体环节，不把已有要求包装成新增洞见。

### 2. 应从什么最原始的材料开始，而不是已被消化的结论？

点名材料及需要的部分，并说明现有摘要或转述可能隐藏什么。例如：

- 排障：实际输入、原始日志、源码及运行轨迹，而非故障总结。
- 业务分析：交易明细、事件记录、访谈原话，而非汇总报表或行业观点。
- 研究：官方原文、原始数据、实验记录，而非二手报告的结论。
- 文稿：原稿、事实出处、目标读者的原始反馈，而非修改意见摘要。

核对来源、时间、定义、单位、口径和代表性；一手材料也可能失真，多个转述同一出处的来源不算独立佐证。

区分已提供、执行时需取得和当前不可得的材料。缺失时说明替代来源及结论限制，不假装已经查阅，也不把资料缺失变成无限扩张的收集任务。

### 3. 具体采用什么方法和工具？

将必要动作落实为：**具体输入 → 分析或处理方法 → 工具 → 产生的证据**。

点名适合当前问题的方法和工具，并说明它们解决哪个不确定性。例如“用 SQL 按渠道与注册周重算留存，检查总体下降是否来自用户构成变化”，而不是“使用数据工具深入分析”。

优先采用现有环境或用户已使用的工具。尚不清楚环境时，说明所需能力或条件化选择，不虚构可用性，不为显得专业堆砌工具。诊断中的拟用方法不代表已经执行。

### 4. 除了你或我，什么能证明结果正确？

明确以下四项：
- **主张**：具体要验证什么。
- **依据**：对应的独立数据、原文、可复现测试、领域标准或真实使用表现。
- **通过条件**：观察到什么才支持该主张。
- **推翻条件**：什么反例、替代解释或失败现象会使结论不成立。

验收要能约束结论，不能只是 AI 自评、用户觉得满意、工具调用成功，或用同一套假设重复生成答案。阈值来自用户约束、适用标准或有依据的业务要求；未确定的阈值标为待校准，不凭空设定。

没有唯一答案的任务，分别检验事实、约束和预期效果，保留审美与偏好判断的边界。证据不足时，明确最多能支持什么结论。

## 三、重写提示词

在四项诊断之后，给出一段可复制、可独立执行的新提示词。把诊断转成执行要求，而不是再抄一遍解释。

新提示词包含：
1. 原目标、对象、交付形式和资源约束。
2. 专家补足的必要动作，以及优先解决的关键问题。
3. 具体原始材料、方法、工具和执行步骤。
4. 独立验收依据、通过条件、反例与证据不足时的处理。
5. 最终交付要求和停止条件。

所有新增要求都应能追溯到四项诊断。删除装饰性流程、无关主题和附加交付物。诊断需要保留证据，不等于要求另交一份长篇证据报告；按原交付形式呈现必要依据即可。

使用当前任务的具体内容，不留下泛化占位符或“按上面的方法”等指代。明确区分事实、推断和假设，要求执行者如实报告实际取得的材料和验证结果。

## 四、交付检查与停止

按顺序交付：**四项诊断 → 重写后的提示词**。说明保持了哪些关键边界；若必须改变边界才能达到预期深度，明确指出冲突并让用户决定，不静默扩大任务。

提交前检查：四问是否都有具体答案？新指令是否准确纳入这些答案？是否保留原范围和交付？是否把计划误写成完成事实？

重写完成即停止，不自动执行原任务。只有用户另行明确要求执行时，才在授权范围内使用新指令开展工作。

## 示例

原提示词：“分析本月留存下降的原因，给我一页建议。”

**四项诊断：**
1. **专家补足**：先核对留存定义，再按注册周与渠道拆分，区分用户构成变化和同类用户表现变差；否则总体下降容易被误判为产品问题。
2. **原始材料**：用户级注册与活跃事件、渠道归因、埋点变更记录，而非月度留存汇总；核对观察窗口是否完整。
3. **方法工具**：用现有 SQL 工具重算统一口径的分群留存，按基期渠道权重重算本月指标，检查构成变化是否足以解释下降。这里只设计方法，尚未查询数据。
4. **独立验收**：用独立计数路径复核关键分子分母并抽查原始事件；若同渠道、同成熟度用户仍明显下降，则“仅由渠道构成导致”的解释不成立。观察性数据只支持解释线索，不直接证明因果。

**重写提示词：**
> 分析本月留存下降的原因，仍只交付一页建议，不扩展为完整增长研究。先确认现行留存定义与比较窗口，取得用户级注册和活跃事件、渠道归因及埋点变更记录，用现有 SQL 工具重算总体及注册周、渠道分群留存；仅比较观察窗口完整的群体。按基期渠道权重重算本月指标，区分用户构成变化与同类用户表现变化。用独立计数路径复核关键分子分母，并抽查原始事件；主动检查“仅由渠道构成导致”的解释是否被分群结果推翻。将已验证事实、可能解释与因果假设分开；缺少材料时标明不能支持的结论。一页内给出最有证据支持的解释、关键依据、限制及针对性建议，达到这些条件即停止，不新增研究主题或报告。
